# Talk2ESP 实现计划总览（Milestones）

> **关联：** `docs/PRD.md`、`docs/ARCHITECTURE.md`
> **制定日期：** 2026-06-28-0328
> **说明：** 本文件是各里程碑总览。每个里程碑（M）有独立详细计划文件 `M<n>-<name>.md`，采用 TDD、小步、频繁提交。按增量交付，每里程碑产出可验证的可用软件。

## 里程碑划分

| 里程碑 | 目标 | 验证标准 | 详细计划 |
|---|---|---|---|
| **M0** | Tauri 骨架 + 前后端通信打通 | 应用可启动；前端 invoke 后端命令返回串口列表 | `M0-tauri-skeleton.md` |
| **M1** | 设备/串口层 | 自动扫描识别两块 S3；串口监控可读可发 | `M1-device-serial.md` |
| **M2** | 工具链层 | arduino-cli 编译 + esptool 烧录经应用触发完成，日志流式推送 | `M2-toolchain.md` |
| **M3** | AI 适配层 | OpenAI 兼容 + Claude 对话与代码生成跑通 | `M3-ai-adapter.md` |
| **M4** | 安全层 + 型号描述表 | 引脚黑名单校验 + 危险代码告警生效 | `M4-safety-chips.md` |
| **M5** | 项目/存储层 | 项目文件夹读写、对话记录、各阶段日志持久化 | `M5-project-storage.md` |
| **M6** | 编排器（流水线状态机） | 需求确认→代码→编译→烧录→验证闭环，含失败重试 | `M6-orchestrator.md` |
| **M7** | 前端完整界面 | 对话/设备/串口/项目/设置五大视图联调 | `M7-frontend.md` |
| **M8** | 闭环验证（双板自测） | 端到端跑通「GPIO1方波+GPIO2回显」全流程 | `M8-e2e-verify.md` |
| **M9** | 示例库 + 打包发布 | 内置6类示例；Windows 安装包 sidecar 打包 | `M9-examples-release.md` |

## 依赖关系
```
M0 ──> M1 ──> M2 ──> M6
                │
M0 ──> M3 ──────────────> M6 ──> M7 ──> M8 ──> M9
M0 ──> M4 ──> M6
M0 ──> M5 ──> M6
```
M1/M2/M3/M4/M5 可在 M0 后部分并行，但 M6（编排器）依赖全部五层。

## 分支策略
- 每个 M 从最新 main 拉分支 `m<n>-<name>`；
- 合并 main 前需通过该 M 的验证标准 + 代码审查；
- 严格遵循 AGENTS.md：不在 main 开发、中文提交信息、文档同步。
